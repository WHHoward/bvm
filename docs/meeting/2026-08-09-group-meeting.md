## 2. 上次汇报回顾（BQ 尝试）→ 本周期结论

**7/13-7/17 的 BQ 尝试**（上次已汇报）：低 IC 缩放 v1-v3、K 元件变压器——全部失败。

**本周期补充验证**：BQ v4（IC 顺序反转修复）实施并独立验证 → **Gate 未通过**。

**最终结论（8 轮实验 0 成功，全部可复现）**：

| 被排除的假设                  | 排除方式                                                  |
| ----------------------------- | --------------------------------------------------------- |
| 降低 BJs IC 能匹配 68µA 输入 | L_J 矛盾（数学成立）：IC↓→L_J↑→电流传递↓，净效应抵消 |
| 变压器能放大脉冲电流          | ps 时间尺度互感耦合能量不足 + 初级分流                    |
| BJL1 吞噬信号是唯一根因       | 部分证实但非完整根因（v4 后 BJL2 也不触发）               |
| 提高 BJL2 IC 能增强输出       | 相反：输出传递路径死亡，v4 比 v2 差 5.5×                 |
| BJs 能产生干净单翻转          | 任何过驱动 ≥1.4×IC 即电压态滑移，从未离散输出           |

**冻结的物理根因（3 条）**：

1. **BJs 裸结无外部阻尼**：βc≈5.4 欠阻尼（jjmit 所有结固有，与 area 无关）；标准 JTL 靠 RB+LRB 阻尼网络 + 70% 偏置才干净翻转，BQ 输入结两者皆无
2. **电流源注入 = 通量泵**：结翻转后输入电流持续泵磁通，滑移量由窗口决定（602-829 SFQ/300ps），与 SFQ 计数无对应
3. **输出级驱动不足**：v2/v4 输出 ~100µA < ColdFlux JTL 阈值 250µA，下游收不到

> **结论**：BQ 拓扑（裸结输入 + 并联输出结构）结构性不适配 BVM 的慢读出电流，**停止缩放迭代，转向专用接口元件**。

## 5. 路线转向：DCSFQ_BVM 新元件（H7 主攻方向）

**为什么 DCSFQ 骨架**——BQ 的三个结构死因它全部结构性解决：

| BQ 死因          | DCSFQ 解法                                                |
| ---------------- | --------------------------------------------------------- |
| 裸结欠阻尼       | **每个结都有 RB+LRB 阻尼网络**（ColdFlux 标准做法） |
| 输出级推不动 JTL | 输出结 B3=250µA + L6 同配方 →**天然 JTL 兼容**    |
| 持续电流通量泵   | **阈值判别器**：电流超阈值才触发一次                |

**设计决策（8/6 用户拍板）**：新元件（非修改 BQ）+ 方案一最小缩放（输入级 B1/B2 225→80µA，输出级冻结 250µA）。替代方案（门控偏置、双端口时钟、修 BQ）保留为后备。

## 8. 组会可能的问题与回答要点

**Q: BQ 的 8 轮失败是不是参数没调好？**
A: 不是参数问题，是拓扑问题：BJs 裸结欠阻尼是结构性缺陷（标准 JTL 有阻尼网络而 BQ 没有）；v4 反转 IC 顺序后输出级反而死亡，说明问题在结构而非参数。L_J 矛盾是数学证明：降低 IC 必然增加输入电感、减少电流传递，净效应抵消。

**Q: 为什么换 DCSFQ 而不是继续修 BQ？**
A: DCSFQ 是 ColdFlux 已验证的标准拓扑：每个结有阻尼、输出与 JTL 同配方、本身是阈值判别器——BQ 的三个死因它全都没有。且文献中 BVM 的读出感测就是外部接口方案（Karamuftuoglu SUST 2024），我们有独立的接口表征创新点。

**Q: 缩放版的阈值目标怎么定的？**
A: 实测驱动：下界来自 R0 窗口 SE 边沿振铃（±40µA），上界来自过驱动多滑移（≤1.5×IC）——窗口 45-55µA，Phase 1 的 V2 扫描裁决。

**Q: 现在最大的风险是什么？**
A: 两个：① 输入耦合效率（0.285）——如果输入网络调整后仍无法在 68.4µA 下产生干净单 SFQ，需启用门控方案（方案二）或改 BVM 输出级（H8，代价是破坏冻结基线）；② BVM 写入是多涡旋态（JM1 +5.93 SFQ），"读1→恰好1 SFQ"最终还需存储侧配合。

**Q: 时间表？**
A: Phase 1 预计 1-2 周；论文 §3-6 并行起草；正结果后补 §7 并投稿。

# 附录 C — 术语速查（组会自用）

## C.1 BVM：模型、参数、输出行为

**模型**：jjmit（Ic×RN=1.6mV；icrit=0.1m → IC=area×100µA，rn=16Ω，cap=0.07pF，vg=2.8mV）。

| 结          | area (IC)          | 角色                 |
| ----------- | ------------------ | -------------------- |
| B_JM1       | 1.2 (120µA) + 6Ω | 存储环主结（带阻尼） |
| B_JM2       | 1.4 (140µA)       | 存储环副结           |
| B_JS1/B_JS2 | 0.74 (74µA)       | 读出开关结           |

输出链：L_PSL(0.5p) → **R_SL(12Ω)** → L_SL(0.4p) → SL 端口；端口：WL（写字线）/BL（位线）/SE（读使能）/SL（读出）。

**输出行为**（实测）：磁通→电流转换；R1 读出 43.9-97.8µA（负载相关）、FWHM 6.8-11.2ps、**正负振荡多摆动瞬态**（12Ω 实测 +74→−18.7→+32→−15.6µA）、Zth≈40Ω；读"0" ~1.4µA；写入多涡旋（+5.93 SFQ）。

## C.2 BJs 是什么

**BJs 属于 BQ，不属于 BVM**。BQ 三个结：**BJs（s=sense，输入感测结，IC=50µA，无分流无阻尼——"裸结"，8 轮实验滑移的源头）**、BJL1（DC 回流，36µA）、BJL2（输出隔离，54µA）。

## C.3 R1 读出 68.4µA 时的负载

基线负载 = **8×jjmit(area=3.2, IC=320µA) 串联链 → BQ 输入**。68.4µA 是"链+BQ 输入"联合加载值：纯链接地 79.55µA，BJs 分流 ~11µA。**68.4µA 不是固有输出，随负载 44-98µA 变化。**

## C.4 sfq_metrics.py 的作用

Step 0 冻结口径的落地工具：CSV → JSON 指标（每结 net_delta / max_excursion / total_variation / **fast_events（|ΔP|>0.3 SFQ/0.1ps，真 SFQ 判据）** / max_dPdt + 峰值列），附带 CSV sha256 + git_head。**核心价值：机器区分"电压态滑移（慢）vs 离散 SFQ（快）"，取代人工读图。**

## C.5 边沿触发 vs 电平触发（G2）

|          | 边沿触发                         | 电平触发                           |
| -------- | -------------------------------- | ---------------------------------- |
| 触发条件 | 输入**变化的瞬间**产生事件 | 电平**超过阈值期间**持续触发 |
| 类比     | 门铃（按的动作触发，按住不响）   | 水龙头（开着一直流）               |
| 持续输入 | 相位恒定零累积                   | 持续滑移（通量泵）                 |

实测 DCSFQ = **边沿触发**（148ps 恒定零累积；bump/sustained 事件逐位一致）→ 方案一（无门控）成立。nuance：边沿触发是"每个边沿一次"，BVM 输出振荡多摆动 = 多个候选边沿 → V2 仍需阈值+时序窗口保证"恰好 1 个"。

## 10. 本日最重要事件：P() 单位事故（计量审计）

**发现**：JoSIM 相位模式的 `P(...)` 输出是 **raw phase，单位弧度（rad）**，不是磁通量子 Φ₀ 单位。旧计量脚本 `sfq_metrics.py` 把 rad 数值直接当"圈数/SFQ 数"用，导致一系列错误结论。

**三个独立验证**（8/9 完成）：

1. JTL 输入弧正弦匹配：`7.0574 rad = 2π + arcsin(0.7)`——精确符合
2. 单结激励：`219.91 rad = 精确 35.000 圈`（除以 2π 后整数）
3. 旧基线重算：BJs `+0.998 圈`、JM1 `−0.94 圈`——恰好是单涡旋

**被纠正的结论**（旧记录已全部标注失效）：

| 旧结论                   | 实际情况                             |
| ------------------------ | ------------------------------------ |
| "BVM 多涡旋 +5.89 圈"    | 5.89 rad = 0.94 圈 =**单涡旋** |
| "300µA 多滑移爆发"      | 每结约 1 圈（除以 2π 后）           |
| "45–55µA 触发目标"     | 基于错误前提，撤回                   |
| `fast_events` = 脉冲数 | 过阈值**采样点数**，不是事件数 |

**仍然有效**（电流/电压类测量不依赖相位单位）：接口规格（43.9–97.8µA、Zth≈40Ω、FWHM 6.8–11.2ps）、0.285 输入耦合、md5 确定性、BQ v4 电压态滑移机制（这是电压行为，结论不变）。

**启示**：以后所有相位结论先算 `圈数 = Δφ_rad/(2π)`，任何"事件数"都必须是稳定窗 + 控制下的离散相位平台，不能是过阈值采样数。

### 16.2 commit 权限设计：执行者不提交

- M4 合同授权 `commit: false`：执行者写完产物**一行 commit 都不执行**，产物以原始工作树状态留给 Codex

### 16.3 完整工作环境 vs 合同快照（一次实战发现）

把 master 新机制（mailbox、记忆整理、文档）同步进 worktree 时发现：**3 个协议文件**（handoff SKILL、CLAUDE_EXECUTOR、HANDOVER）**不能换新版**——它们在合同 `read_paths` 内、哈希被 scope manifest 绑定，换版会破坏机械校验（`verify-task`）。处理：只同步非 read_paths 内容 + worktree 根放 `WORKTREE_NOTES.md` 说明快照版本与审计指引。**验证：同步后 verify-task 仍 VERIFIED。**

### 16.4 生命周期防积累

每个任务一个 worktree（命名 `claude/<task-id>` + `JoSIM-<task-id>` 目录）；审计 ACCEPTED + 产物并入 master 后清理；串行任务（M4→M5→M6）不并行开 worktree；新任务前先 `git worktree list` 查遗留。当前活跃：仅 1 个（M4）。
