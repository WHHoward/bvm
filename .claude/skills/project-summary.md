# 项目总结与整理

## 触发条件

当用户提到以下关键词时调用：
- 总结项目、整理项目、项目总结、归档、收尾、清理项目
- "帮我梳理一下项目"
- "整理一下现在的进度"
- "记录一下变更/改动"

## 工作流程

### ⚠️ 第一步：记录变更到 CHANGELOG.md（每次必做，不可跳过）

**这是最重要的一步。** 每次执行总结前，先回顾当前会话做了什么，追加到 `CHANGELOG.md` 中。

```markdown
## YYYY-MM-DD — 简短标题

### 做了什么
- 列出具体变更（文件、操作、结果）

### 为什么
- 解释原因

### 影响
- 这项变更对项目的后续影响
```

**规则**：
- **只追加，不删除，不覆盖已有条目**
- 每次记录的日期用当天真实日期
- 标题用一句话概括本轮最主要的工作
- 如果当前会话有多轮不相关的变更，可以分多个条目
- CHANGELOG.md 在项目根目录，可以直接查看，也可以提交到 git

### 第二步：扫描现状

```bash
find . -name "*.md" -type f | grep -v node_modules | grep -v build | grep -v .git
find . -name "*.html" -type f
find . -name "*.csv" -type f
find test/ -type d | sort
```

### 第三步：分类评估

| 判断 | 操作 |
|------|------|
| 内容已在 memory/ 中 | 删除 |
| 旧版本可重新生成 | 删除 |
| 唯一的知识来源 | 提取到 memory/ |
| 当前工作必需 | 保留 |

### 第四步：更新记忆

确保以下内容已写入 `memory/`：
1. **项目结构** — 目录布局、关键文件
2. **关键技术** — 物理原理、模型参数、设计规则
3. **当前状态** — 什么工作了、什么没工作、下一步
4. **Skill 使用规范** — 触发规则

### 第五步：更新 MEMORY.md

```markdown
- [标题](file.md) — 一句话描述
```

### 第六步：清理

删除所有可重新生成或已归档的文件：
- 旧 HTML 可视化（可用 josim-plot2 重新生成）
- 旧 CSV 仿真结果（可用 josim-cli 重新生成）
- 重复的 .md 文档（已提取到 memory/）

### 第七步：更新 memory/project-summary.md

同步更新综合总结中的「已完成工作」「已知问题」「下一步方向」等章节。

### 第八步：报告

```
总结完成：
- CHANGELOG.md 已更新（新增 X 条记录）
- 删除 Y 个冗余文件
- 项目状态：<一句话>
```

## 关键文件位置

| 文件 | 位置 | 用途 |
|------|------|------|
| **CHANGELOG.md** | **项目根目录** | **人类可读的完整变更历史（只追加）** |
| memory/project-summary.md | ~/.claude/projects/.../memory/ | 当前状态快照（AI 加载） |
| memory/MEMORY.md | ~/.claude/projects/.../memory/ | 记忆索引（AI 加载） |
