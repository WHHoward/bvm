我已审阅 research/WORKFLOW-copilot-review-proposal.md。方向可取：让 Copilot 在 Claude receipt 后做只读、独立的证据复核，Codex 保留最终采纳。

建议不要直接按草案落地：
1. 当前 M4-003 已由 C01 ACCEPTED，不能再作为 DRAFT 试点；优先考虑 M12 或 M5 的纯计量实现部分。
2. 新增 review.yaml 就必须有 schema 与机械校验；建议单设 evidence-review 记录，而非复用最终 audit verdict。
3. review 必须绑定 request/ACK/receipt SHA-256、审查 Git HEAD、范围、命令/退出码/日志哈希、逐条验收证据、未知项与 claim-ceiling 检查。
4. review 的 PASS/REWORK 与物理 PASS/FAIL/INCONCLUSIVE 必须分开；INCONCLUSIVE 可以是有效研究结果。
5. 路线、物理 Gate、指标冻结、论文主张、证据冲突或单位/窗口/收敛争议，Codex 仍须从 raw 亲自复核，不能只读 review 摘要。
6. “独立”应定义为未参与实现、只读、固定快照复核；共享文件系统不提供身份或命令历史证明。
7. 新方案还应修复当前 verify-task 的历史语义：审计后正常更新 HANDOVER/todo 会使 live frozen-file 比较误报旧任务失效，应区分执行时快照验证与当前漂移检查。
