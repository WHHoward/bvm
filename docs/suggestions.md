# JoSIM 项目建议与未来规划

本文基于当前仓库代码、测试结构，以及 memory 中沉淀的实验结论整理而成。目标不是罗列想法，而是把 JoSIM 在“超导存内计算仿真与优化”这条主线上的下一步工作拆成可执行、可验证、可迭代的路线。

## 1. 总体判断

当前项目已经具备不错的基础：

- JoSIM 本体是一个可构建、可安装、可扩展的仿真器。
- ColdFlux 标准元件库已经形成规模，且一部分元件完成了明确验证。
- BVM、BQ、T1 这三类电路已经把“存储、接口、运算”三层都搭出来了。

但从项目推进方式上看，现在最需要补的不是“再多加几个电路”，而是把研究成果工程化：

1. 把单元级验证、链路级验证、系统级验证分层。
2. 把关键接口的物理约束写成可复用的设计规范。
3. 把文档、测试和版本状态保持同步。

如果这三件事不做，后续标准元件库扩张越快，维护成本越高。

## 2. 当前最值得优先处理的方向

从收益和风险看，我建议现在的优先级大致是：

1. 标准元件和关键链路纳入正式回归。
2. 解决 BVM -> BQ 的接口耦合问题。
3. 完成 T1 全加器的系统级验证。
4. 再向阵列、接口标准化和参数自动化扩展。

这里面第二点和第三点最关键，因为它们分别代表了“存储到缓冲”的接口瓶颈，以及“从链路到计算”的系统瓶颈。

## 3. 对 BVM -> BQ 耦合问题的更具体分析

这是目前最像“平台级瓶颈”的问题。

### 3.1 问题本质

从 memory 中已经确认，BVM 的 SL 输出阻抗大约是 130Ω，而 BQ 输入阻抗大约是 350Ω。这个不匹配会导致电流传递效率偏低，只有一小部分激励真正到达 BQ 的工作阈值。

这意味着问题并不是“BVM 不工作”或“BQ 不工作”，而是“两个单元各自独立成立，但接口不成立”。

对于存内计算来说，这类问题比单元逻辑错更麻烦，因为它不会在单元测试里直接暴露，而是只在级联时出现。

### 3.2 为什么它必须优先处理

如果这个接口不稳定，后续所有上层目标都会被拖慢：

- BVM 阵列无法稳定读出到 BQ。
- BQ 无法作为统一的缓冲或量化接口层。
- T1 以及更上层运算模块无法可靠接收前级输出。

换句话说，BVM -> BQ 是你们当前链路里最典型的“系统集成门槛”。

### 3.3 更具体的技术判断

我认为这里至少有四个子问题需要分开看：

1. **阻抗匹配问题**：输出级太“硬”，而输入级需要更明确的电流注入。
2. **阈值问题**：BQ 的有效触发区间与 BVM 输出电流分布之间存在落差。
3. **时序窗口问题**：即使平均电流足够，脉冲到达顺序和持续时间也可能不满足触发条件。
4. **模型兼容问题**：BVM 与 BQ 当前使用的 JJ 参数集不同，能不能级联，不只是电路几何问题，也和模型工作点有关。

### 3.4 更可行的解决路径

我建议把解决方案分成“三层实验”，而不是直接赌一种方案：

#### 路径 A：低 IC 检测结

把 BQ 前端设计成更低阈值的检测级，让它能接受更小的输入电流。

优点：

- 改动集中在接口层。
- 容易做参数扫描，能快速找到有效窗口。
- 可以尽量保留 BVM 的主体结构。

风险：

- 可能牺牲噪声裕量。
- 输入太敏感后，误触发和多触发风险会上升。

#### 路径 B：变压器耦合或等效电流放大

通过互感或等效耦合结构提升传递效率。

优点：

- 更接近物理接口层的“真正匹配”。
- 如果做成标准接口，后续可以复用于其他存储单元。

风险：

- 需要额外的电路元件和参数调优。
- 会增加设计复杂度，也可能引入新的时序问题。

#### 路径 C：重设计 BVM 输出级

如果 SL 输出天然偏弱，就从源头降低输出阻抗或者重构输出路径。

优点：

- 一旦成功，接口更稳定。
- 可以把输出级设计成适配 BQ 的统一标准。

风险：

- 这是代价最大的方案。
- 可能影响已经验证通过的 BVM 独立行为。

### 3.5 我建议的实验顺序

最实际的做法是：

1. 先做一个固定 BVM 输出、扫 BQ 输入阈值的接口测试。
2. 如果阈值窗口太窄，再引入耦合增强手段。
3. 如果耦合增强后仍不稳定，再回到 BVM 输出级重构。

这样做的原因是，先确认问题到底是“阈值不够”还是“接口结构不对”，可以避免一开始就重写整个存储单元。

### 3.6 建议的验收指标

建议你们把 BVM -> BQ 的通过标准写成硬指标，而不是主观描述：

- 输入到达 BQ 时能稳定触发一次明确输出。
- 不出现多次触发或误触发。
- 在一定参数扰动下仍保持工作。
- 输出可被后级 JTL 或等效负载稳定识别。

只要这四条没有同时满足，这个接口就不应被视为可用。

## 4. 对 T1 全加器的更具体分析

T1 的角色和 BVM -> BQ 不一样，它不是接口层，而是系统层的“计算基准单元”。

### 4.1 为什么 T1 值得单独作为重点

T1 本质上是把前级输入量化为可用 SFQ 输出的计算单元，它既承担时序控制，也承担逻辑正确性验证。

如果说 BVM -> BQ 是“存到算”的接口门槛，那么 T1 就是“算得对不对”的主验证对象。

一旦 T1 稳定，后续你们做：

- 存内计算演示，
- 小规模阵列读出后运算，
- 更复杂的时序组合逻辑，

都会有一个可复用的基线。

### 4.2 目前 T1 最大的风险不是“能不能跑”，而是“是否足够稳健”

T1 这类电路最容易出现的情况是：

1. 单个输入组合能通过。
2. 但一换成全真值表，某些边界情况失败。
3. 再做时序偏移或脉冲宽度扰动，结果又变了。

这说明 T1 的问题通常不是结构完全错误，而是工作窗口太窄。

所以对 T1 的验证不能只停在“某次能输出对的结果”，而要继续做鲁棒性检查。

### 4.3 T1 应该补的验证层次

我建议至少补三层：

#### 1）功能正确性

把全加器的真值表逐项跑完，至少验证：

- 和位是否正确。
- 进位是否正确。
- 是否存在漏脉冲或多脉冲。

#### 2）时序窗口

对输入脉冲到达时间做系统扫参，检查：

- 数据和时钟的相对顺序是否敏感。
- 最小安全间隔是多少。
- 轻微 skew 下是否还能正常工作。

这一步很重要，因为你们已经在 memory 里确认了“数据先于时钟”是基本规律，T1 也必须遵守这个规律。

#### 3）参数鲁棒性

围绕偏置电流、JJ 模型参数、脉冲宽度、负载方式做局部扰动，确认 T1 不是只在一个非常窄的点上工作。

### 4.4 更进一步的建议

如果 T1 未来要接入 BQ 或阵列输出，我建议把它拆成两个版本：

- 一个是“研究验证版”，优先证明功能。
- 一个是“接口兼容版”，优先证明可级联。

这会比把所有要求都塞进一个版本里更清晰，也更容易维护。

### 4.5 T1 的验收标准建议

建议把 T1 的验收定义成以下几项：

- 全真值表通过。
- 在一定时序扰动下仍通过。
- 在小范围参数扰动下仍不失稳。
- 输出可被后续模块稳定识别。

只做静态真值表是不够的，因为超导逻辑的核心风险往往在时序边界和能量窗口，不在单次功能点。

## 5. 中长期规划建议

### 短期：把研究成果变成可回归资产

这一阶段最重要的是把已经验证过的东西固定下来：

- 标准元件回归。
- BVM、BQ、T1 的基线测试。
- 关键脉冲规则、偏置规则、模型规则写进文档。

### 中期：做成“链路可用”而不是“单元可用”

这一阶段重点是：

- 打通 BVM -> BQ。
- 把 T1 接到前级输出上。
- 建立小规模阵列到运算模块的最小演示链。

### 长期：做接口标准化和参数自动优化

如果前两阶段做好，下一步真正有价值的方向是：

- 定义统一的接口规范。
- 建立参数扫描和自动筛选流程。
- 用回归测试驱动电路设计，而不是靠手工经验反复试。

这一步会决定项目能否从“成功案例集合”变成“可持续平台”。

## 6. 如果只能先做三件事

1. 把 BVM -> BQ 做成最小可复现接口测试，并建立明确验收标准。
2. 把 T1 的真值表、时序窗口和参数鲁棒性补齐。
3. 把标准元件、BVM、BQ、T1 的测试纳入正式回归体系。

这三件事做完，项目就会从“已经有很多成果”变成“有稳定方法论和可迭代平台”。
